# DOCX Quality Checklist

## Content
- [ ] The document serves the requested purpose and audience.
- [ ] Names, dates, numbers, and references are grounded in supplied information.
- [ ] No unintended placeholders remain.
- [ ] Spelling, grammar, and terminology are consistent.
- [ ] Headings accurately describe their sections.

## Structure
- [ ] Heading levels are logical.
- [ ] Lists use Word list formatting where practical.
- [ ] Tables have clear headers.
- [ ] Sections and page breaks are intentional.
- [ ] Headers and footers are consistent.

## Formatting
- [ ] Fonts, sizes, spacing, and alignment are consistent.
- [ ] Margins and orientation are appropriate.
- [ ] Tables fit within page boundaries.
- [ ] Images retain aspect ratio.
- [ ] No excessive blank paragraphs or manual spacing hacks remain.

## Accessibility
- [ ] Heading styles are semantic.
- [ ] Hyperlink text is descriptive.
- [ ] Informative images have alt text where supported.
- [ ] Color is not the only information cue.
- [ ] Tables remain understandable when read linearly.

## Technical validation
- [ ] The output is a valid DOCX package.
- [ ] The document reopens with python-docx.
- [ ] Expected paragraphs, tables, and images are present.
- [ ] Rendering completed when required dependencies are available.
- [ ] Every rendered page was reviewed when layout fidelity matters.

## Delivery
- [ ] Output file is clearly named.
- [ ] Source was preserved unless replacement was requested.
- [ ] Rendering limitations are disclosed.
- [ ] No validation is claimed unless it was performed.
